# 数据模型与算法

> 文档编号：DM-LeadOps-001　　版本：v1.0　　日期：2026-10-04　　负责人：张路

## 1. 数据分层

- **ODS**：原始接入层，与源端一致。
- **DWD**：明细层，清洗、标准化、拉宽维度。
- **DWS**：汇总层，按主题/粒度聚合。
- **ADS**：应用层，面向业务查询。
- **DIM**：维表（车型、城市、门店、销售、经销商）。

## 2. 关键数据模型

### 2.1 OneID 表

```sql
CREATE TABLE dim_oneid (
    oneid         VARCHAR(32) PRIMARY KEY,
    main_phone_md5 VARCHAR(64),
    status        VARCHAR(16),      -- active/merged/deleted
    created_at    TIMESTAMP,
    updated_at    TIMESTAMP
);

CREATE TABLE dim_oneid_mapping (
    oneid       VARCHAR(32),
    id_type     VARCHAR(32),   -- phone_md5/device_id/wechat_openid/...
    id_value    VARCHAR(128),
    weight      DOUBLE,
    source      VARCHAR(32),
    created_at  TIMESTAMP
);
```

### 2.2 用户行为明细（DWD）

```sql
CREATE TABLE dwd_user_event (
    event_id     VARCHAR(64),
    oneid        VARCHAR(32),
    event_type   VARCHAR(32),      -- view_model/configure/lead_submit/call/arrive/deal
    event_time   TIMESTAMP,
    channel      VARCHAR(32),
    properties   STRING,           -- JSON
    dt           DATE
) PARTITION BY (dt);
```

### 2.3 用户标签宽表（DWS）

```sql
CREATE TABLE dws_user_tag (
    oneid        VARCHAR(32),
    tag_date     DATE,
    -- 基础
    age_range    VARCHAR(16),
    city         VARCHAR(32),
    city_tier    VARCHAR(16),
    gender       VARCHAR(4),
    occupation   VARCHAR(32),
    -- 行为
    view_cnt_7d INT,
    view_cnt_30d INT,
    config_complete_7d INT,
    lead_submit_30d INT,
    arrive_cnt_30d INT,
    -- 模型
    intent_score INT,
    intent_level VARCHAR(4),
    churn_risk   DOUBLE,
    pref_models  ARRAY<STRING>,
    price_band   VARCHAR(16),
    PRIMARY KEY (oneid, tag_date)
);
```

### 2.4 Bitmap 聚合表

```sql
CREATE TABLE dws_user_tag_bitmap (
    tag_id       INT,
    tag_value    VARCHAR(64),
    user_bitmap  BITMAP BITMAP_UNION
)
AGGREGATE KEY(tag_id, tag_value)
DISTRIBUTED BY HASH(tag_id) BUCKETS 32;
```

## 3. 标签体系

### 3.1 分类
- **基础属性**：地域、年龄段、性别、职业、收入段位、家庭结构。
- **行为意向**：浏览车型、配置器、询价、留资、到店、试驾、置换询问。
- **模型预测**：意向分 L0–L5、车型偏好、价格带、流失风险。
- **业务标签**：会员等级、客户来源、所属销售、所属门店。

### 3.2 标签规范
- 每个标签含：id、名称、分类、取值类型（枚举/布尔/数值/数组）、刷新频率（实时/日/周）、负责人、血缘。
- 版本：标签逻辑变更保留历史版本，T+1 回灌。
- 血缘：标签 → SQL/模型 → 原始表字段。

### 3.3 标签示例

| tag_id | 名称 | 分类 | 刷新 | 逻辑 |
|---|---|---|---|---|
| 1001 | 高意向等级 | 模型 | 日/实时 | 意向分分位切桶 |
| 1200 | 城市等级 | 基础 | 日 | 维表映射 |
| 3001 | 近30天留资 | 行为 | 日 | `lead_submit` 事件去重 |
| 3010 | 近7天浏览SUV | 行为 | 日 | `view_model` + 车型过滤 |
| 4001 | 流失风险 | 模型 | 周 | Survival 模型输出 |

## 4. 意向评分模型

### 4.1 目标
预测用户未来 90 天内购车概率，输出 0–100 分，按分位切 L0–L5。

### 4.2 样本
- 正样本：历史 180 天内发生成交事件的用户。
- 负样本：同期活跃但未成交的用户（1:3 下采样）。
- 时间窗：训练窗口 90 天，预测窗口 90 天。

### 4.3 特征
约 200 维，分五大类：
- 基础：年龄段、城市等级、职业、收入段。
- 行为：浏览/配置/询价/留资/到店 7/30/90 天次数与衰减加权。
- 时序：行为峰值、首次/最近时间距今。
- 交叉：车型 × 价格带、渠道 × 时段、城市 × 车系。
- 外部：季节、促销期、油价、地区经济指标。

### 4.4 模型
- 基线：LightGBM（易解释、训练快）。
- 增强：DeepFM + LightGBM Stacking。
- 可解释：SHAP 输出 Top 原因。

### 4.5 评估
- AUC ≥ 0.80，KS ≥ 0.4。
- Lift@Top10% ≥ 5。
- 分战区分车系评估公平性。

### 4.6 训练与部署
- T+1 全量重训（Spark + XGBoost on K8s）。
- MLflow 记录版本、参数、指标。
- Shadow 7 天 → 灰度 5% → 50% → 100%。
- 线上 Triton 推理，QPS 1 万，P99 ≤ 100ms。

### 4.7 监控
- 线上 AUC（成交回传后计算）。
- PSI 监控特征漂移，>0.2 告警。
- 线上线下特征一致性抽样对比。

## 5. 推荐召回与排序

- **多路召回**：
  - 协同过滤（ItemCF/UserCF）
  - 向量召回（车型 Embedding + Milvus）
  - 规则召回（同城同价带热销、新车型）
- **排序**：Wide & Deep / DIN，输出车型 Top-N。
- **冷启动**：按人口学特征推荐同类用户热销车型。
- **效果**：CTR、留资率、到店率。

## 6. Lookalike 扩量

- 输入：种子人群 Segment。
- 特征：标签向量 + 行为 Embedding。
- 相似度：Cosine，阈值 0.75。
- 过滤：剔除已覆盖、已退订、已成交。
- 输出：扩量名单，推送到广告 DMP。

## 7. 流失/休眠预警

- 定义：近 30 天无任何行为、意向分下降 > 20 分。
- 模型：Survival Analysis（Cox-PH 基线、DeepSurv 增强）。
- 输出：未来 30/60/90 天流失概率。
- 使用：触发唤醒旅程（内容、券、置换邀约）。

## 8. 归因算法（MTA）

- Last Touch：基线。
- Linear：等权。
- Time Decay：半衰期 7 天。
- Shapley：所有渠道组合均摊；10% 用户采样。
- 输出：渠道/旅程/创意贡献度，用于预算分配。

## 9. 特征平台（Feature Store）

- 在线特征：Redis 存储，Flink 实时写入。
- 离线特征：Iceberg 存储，Spark 批量计算。
- Schema 统一：`feature_group / feature_name / dtype / ttl`。
- 一致性：每日抽样对比，差异 > 1% 告警。
- 版本：Feature Set 带版本，训练与推理指定版本。

## 10. 数据质量

- 规则：空值率、重复率、取值范围、新鲜度、唯一性。
- 工具：Great Expectations + 自研 DQC。
- 异常处理：告警 + 死信队列 + 回溯重跑。
- SLA：ODS 延迟 ≤ 1h，DWS 延迟 ≤ 4h。
