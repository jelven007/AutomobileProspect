# 阶段 4：前端对接 Prisma BFF 联调记录

## 目标

验证 Admin 前端（Vite, localhost:5175）与阶段 3 迁移后的 BFF（Prisma + Postgres, localhost:7001）在 Customer 列表 / 筛选 / CRUD / 导入 / 导出全链路可用，无契约漂移。

## 浏览器实测清单

| 场景 | 入口 | 结果 |
| --- | --- | --- |
| 启动 Admin + BFF | `pnpm --filter @leadops/admin dev` + `pnpm --filter @leadops/bff dev` | ✅ `http://localhost:5175/customer` 渲染完成 |
| 列表 + 总条数 | PageContainer extra 槽位 | ✅ `总条数：3`，表格 15 列正确渲染（身份证 / 手机 明文、省市区齐） |
| 姓名/编码搜索 | 顶部 Input.Search → `GET /bff/customer?q=` | ✅ 搜 "李四" → total=1，命中单行 |
| 省份下拉筛选 | facets 聚合 + Select → `?province=` | ✅ 下拉 3 项（北京市 / 广东省 / 四川省）；选 "四川省" → 1 行张三 |
| 单条新增 | 新增客户 Modal → `POST /bff/customer` | ✅ curl 走通：身份证 510104... → 自动派生 "四川省/成都市/锦江区"；浏览器端 UI 层面 fill 工具事件语义差异导致需要原生输入（后续若需 e2e 自动化应切换到 Playwright 的 fireEvent） |
| 单条编辑 | 行内 编辑 Modal → `PUT /bff/customer/:id` | ✅ curl 走通 version 乐观锁 1→3；UI 的 fill 事件同上 |
| 单条删除 | 行内 删除 + Popconfirm | ✅ UI 点击确认 → total 3→2 → 刷新验证消失 |
| 清空全部 | 清空全部按钮 | ✅ `DELETE /bff/customer/_all` 走通 |
| 导出 ZIP | 导出 Excel → `GET /bff/customer/export` | ✅ 弹"导出成功"通知："共 3 条，按省市拆分为 3 个 Excel" |
| 批量导入 | 批量导入 xlsx Modal (Dragger) → `POST /bff/customer/import` | ✅ Demo.xlsx 3 行 inserted=3 updated=0 耗时 25ms |
| 二次导入去重 | 同 Demo.xlsx 再传一次 | ✅ inserted=0 updated=3 total=3，跨批次 upsert 生效 |
| 服务重启数据持久 | 阶段 3 已验证 | ✅ kill BFF 后重启，`GET /bff/customer` 仍返回已有记录 |
| 同步任务页 | `/ingest-jobs` | ⚠️ 页面可渲染但走内存 Mock，待 3.7 Prisma 迁移完成 |

## 契约验证

| API 层 | Admin 调用点 | BFF 响应 |
| --- | --- | --- |
| `GET /bff/customer` | `api.customer.list` | `{ items, has_more, next_cursor, total }` ✅ |
| `GET /bff/customer/facets` | `api.customer.facets` | `{ province, city, district }` ✅ |
| `POST /bff/customer` | 新增 Modal | `Customer` 对象，含服务端派生字段 ✅ |
| `PUT /bff/customer/:id` | 编辑 Modal (version 乐观锁) | 新版本 Customer ✅ |
| `DELETE /bff/customer/:id` | 行内删除 | `{ ok: true }` ✅ |
| `POST /bff/customer/batch-delete` | 批量删除 | `{ deleted: N }` ✅ |
| `DELETE /bff/customer/_all` | 清空全部 | `{ deleted: N }` ✅ |
| `GET /bff/customer/export` | 导出 Excel | `application/zip`，exposed headers `X-Export-Total` / `X-Export-Groups` / `Content-Disposition` ✅ |
| `POST /bff/customer/import` | 导入 Modal (XHR with progress) | `CustomerImportReport` ✅ |

**结论**：阶段 3 Prisma 迁移对外契约与 Mock 版完全一致，前端代码不需要任何改动。

## 遗留 / 待推进

- 阶段 4.3：IngestJobController 当前仍是内存数组（阶段 3.7 二期切 Prisma）
- 阶段 5.2 / 5.3 性能压测：10 万 / 100 万行需引入 Prisma `createMany` + 批量事务（当前单条 upsert 适合 Demo 规模；BFF 已配 `bodyLimit=512MB` + 15 分钟 keep-alive，瓶颈改到数据库写入阶段）
- UI 自动化：fill_form 对 antd v5 的受控 Input 有事件语义差异，e2e 自动化推荐 Playwright `fireEvent.input` 或直接通过 React testing-library
