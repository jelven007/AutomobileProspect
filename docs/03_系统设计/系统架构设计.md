# 系统架构设计

> 文档编号：SA-LeadOps-001　　版本：v1.0　　日期：2026-10-04　　负责人：张路

## 1. 设计目标

- 支持亿级用户、十亿级事件的存储与分析。
- 查询低延迟：圈选 P95 ≤ 3s，画像点查 P99 ≤ 50ms。
- 批流一体，线上线下特征一致。
- 模块化、可扩展、可灰度、可观测。
- 安全合规：PII 加密、字段级权限、全链路审计。

## 2. 设计原则

- **分层解耦**：数据层、服务层、应用层各自独立演进。
- **读写分离**：OLAP 做人群圈选，KV 做画像点查。
- **冷热分层**：对象存储冷存，Doris 热查，Redis 加速。
- **声明式配置**：标签、旅程、规则皆可配置，而非硬编码。
- **可演进**：优先规则兜底，再逐步引入 ML。
- **零信任**：服务间 mTLS，最小权限原则。

## 4. 数据流

### 4.1 离线链路（T+1 全量/增量）
```
对象存储/CRM → Spark ETL → Iceberg ODS → DWD/DWS → Doris
                                                   → HBase（画像点查）
                                                   → Bitmap（圈选）
```

### 4.2 实时链路（秒级）
```
埋点/CDC → Kafka → Flink → 实时特征 Redis
                       → 实时打分
                       → Doris 实时写入
                       → 画像增量
```

### 4.3 服务链路
```
运营平台 → 圈选引擎 → Doris Bitmap → 名单落 Redis/文件
                                   → 旅程服务 → 触达网关 → 多通道
                                             → 回传 Kafka → 归因 → 模型迭代
```

### 4.4 关键事件
- `user_identified`（OneID 创建/合并）
- `user_scored`（意向分变更）
- `lead_dispatched`（线索派单）
- `message_sent / delivered / clicked`
- `lead_arrived / deal_closed`
- `model_published / model_drift`

## 5. 部署拓扑

### 5.1 环境
- **Dev**：单节点迷你集群，用于开发。
- **Staging**：生产 1/5 规模，影子库，接真实回流数据。
- **Prod**：全量生产集群，多可用区。

### 5.2 Kubernetes 组织
- 命名空间：`leadops-ingest`、`leadops-core`、`leadops-ml`、`leadops-web`。
- Node Pool：
  - `cpu-standard`（通用服务）
  - `cpu-memory`（Doris、HBase）
  - `gpu-a10`（在线推理）
  - `gpu-a100`（离线训练）
- Ingress：Nginx + ALB，TLS 终止在 ALB。

### 5.3 多活与容灾
- 核心服务跨 3 AZ 部署。
- 对象存储、Kafka 跨 AZ 复制。
- 异地冷备（跨 Region），RPO ≤ 1h，RTO ≤ 4h。

## 6. 关键能力的设计

### 6.1 亿级人群圈选
- 每个标签 → RoaringBitmap。
- Doris Bitmap 列实现 AND/OR/NOT。
- 预聚合物化视图加速高频组合。
- 热门人群结果缓存 TTL 15min。

### 6.2 画像点查
- HBase Rowkey = `hash(oneid)_oneid`，热点均衡。
- 二级缓存：Redis Hash，TTL 1h，LRU 淘汰。
- 冷数据直查 HBase，QPS 10 万时 P99 ≤ 50ms。

### 6.3 批流一致
- 离线特征用 Spark 全量计算 → Iceberg。
- 在线特征用 Flink 实时增量 → Redis。
- Feature Store 保证 schema 与计算口径一致。
- 每日对比抽样，差异 > 1% 告警。

### 6.4 灰度与回滚
- 服务：K8s 蓝绿 + 流量切分。
- 模型：Shadow 7 天 → 5% → 50% → 100%。
- 配置：中心化配置（Apollo/Nacos），一键回滚。

## 8. 服务间调用

- 同步：HTTP/REST（外部），gRPC（内部）。
- 异步：Kafka + CloudEvents 规范。
- 幂等：所有写操作带 `X-Request-Id`。
- 重试：指数退避 + 死信队列。
- 熔断：Sentinel / Resilience4j。

## 9. 存储设计（概览）

### 9.1 Iceberg 表分区
- ODS：`dt / channel`
- DWD：`dt / event_type`
- DWS：`dt / tag_category`

### 9.2 Doris 库
- `dwd_user_event`：用户行为明细（1 年）。
- `dws_user_tag`：标签宽表。
- `dws_user_tag_bitmap`：Bitmap 聚合表。
- `ads_funnel`：漏斗聚合（物化视图）。

### 9.3 HBase 表
- `profile:user`：Rowkey = `hash(oneid)_oneid`；Column Family `basic / tags / score`。
- `profile:behavior`：Rowkey = `oneid_rev_ts`，近 90 天行为。

## 10. 安全架构

- 网络：VPC 隔离，服务间仅内网。
- 鉴权：外部 OAuth2 + JWT；内部 mTLS + 服务 Token。
- 加密：传输 TLS 1.3；存储 SSE-KMS；字段级加密（PII）。
- 密钥：KMS 托管 + 季度轮换。
- 审计：所有变更/导出写入审计日志（Loki + ES），保留 180 天。

## 11. 可观测架构

- Metrics：Prometheus，服务/数据/模型三层。
- Logs：Loki/ELK，PII 自动脱敏。
- Traces：OpenTelemetry + Jaeger，Trace ID 透传。
- Alerts：Alertmanager，分级（电话/企微/邮件）。

## 12. 架构决策记录（ADR 摘要）

| 编号 | 决策 | 原因 |
|---|---|---|
| ADR-01 | OLAP 选 Doris 而非 ClickHouse | Doris Bitmap + 多表 Join 更适合圈选 |
| ADR-02 | 画像点查选 HBase + Redis | 亿级规模 KV 延迟稳定；Redis 做二级缓存 |
| ADR-03 | 流处理选 Flink | 社区成熟、Exactly-once 稳定 |
| ADR-04 | OneID 用图数据库 | 关系复杂、支持溯源与可视化 |
| ADR-05 | 微服务用 gRPC 内网通信 | 低延迟、强类型 |
| ADR-06 | 工作台前端选 React + Antd Pro | 中后台生态成熟、工程效率高 |

## 13. 风险与约束

- Doris 集群运维复杂，需投入 SRE。
- 对象存储单文件过大会拖慢 Spark，需控制在 128MB-1GB。
- Flink 状态过大需 RocksDB + 增量 Checkpoint。
- 模型冷启动期用规则兜底。
