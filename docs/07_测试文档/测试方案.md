# 测试方案

> 文档编号：QA-LeadOps-001　　版本：v1.0　　日期：2026-10-04　　负责人：张路

## 1. 测试策略

| 层级 | 覆盖 | 工具 | 责任人 |
|---|---|---|---|
| 单元测试 | 核心函数、规则、算法 | pytest / JUnit | 研发 |
| 集成测试 | 跨服务链路 | Postman + 自研 e2e | QA |
| 接口测试 | REST/gRPC 接口 | Postman / RestAssured | QA |
| 前端 UI 测试 | 工作台交互 | Playwright / Cypress | QA |
| 性能测试 | 吞吐、延迟 | JMeter / Locust / wrk | 性能工程 |
| 数据测试 | 准确性、一致性 | Great Expectations / 自研 | 数据工程 |
| 模型测试 | 离线评估 + 回放 | MLflow + A/B | 算法 |
| 安全测试 | 渗透、越权、注入 | Burp Suite / 内部红队 | 安全 |
| UAT | 真实业务场景 | 用例清单 | 业务 |
| 冒烟测试 | 核心链路 | 自动化脚本 | QA |
| 回归测试 | 变更影响面 | 自动化 + 手工 | QA |

### 1.1 测试环境
- Dev：研发自测。
- QA：集成测试、接口测试。
- Staging：性能、UAT、灰度前验证（1/5 规模，影子数据）。
- Prod：灰度与线上监控。

### 1.2 测试数据
- 使用脱敏后的生产快照（PII 哈希/替换）。
- 性能测试使用合成数据（亿级 OneID、十亿事件）。

### 1.3 入口准出
- 入口：需求评审通过 + 技术方案评审通过 + 测试用例评审通过。
- 准出：
  - P0/P1 Bug 全部修复；
  - P2 Bug 修复率 ≥ 90%；
  - 性能指标达标；
  - UAT 通过。

## 3. 性能压测

### 3.1 压测目标

| 场景 | 目标 QPS | 延迟 P95 |
|---|---|---|
| 画像点查 | 10 万 | ≤ 50ms |
| 人群预估 | 100 | ≤ 1s |
| 人群导出（亿级） | - | ≤ 10 min |
| 实时打分 | 1 万 | ≤ 100ms |
| 触达下发 | 1 万 | ≤ 500ms |
| 事件消费 | 50 万 | 端到端 ≤ 10s |

### 3.2 压测方法
- 阶梯加压（10% → 50% → 100% → 120%）。
- 持续时间：核心场景 30min，长稳 24h。
- 混合流量：读写比按实际估算。
- 熔断测试：下游故障注入（Doris 节点挂、Redis 延迟）。

### 3.3 容量验证
- 存量数据回放 7 天，验证端到端延迟。
- 模拟 10 倍突发流量，确认限流与降级生效。

## 4. 安全测试

- OWASP Top 10 扫描（XSS、SQLi、CSRF、SSRF）。
- 认证与授权越权测试。
- API 滥用（限流、暴力枚举）。
- PII 导出路径的审计一致性。
- 密钥管理与轮换。
- 定期红蓝对抗（季度）。

## 5. UAT

- 业务负责人提供真实用例清单（覆盖运营、销售、店长、分析师、合规官）。
- 关键场景：UC-01 高意向到店邀约、UC-02 新车上市种草、UC-03 休眠唤醒。
- 验收标准：所有 P0 用例通过；运营方可独立完成"圈人 → 触达 → 看结果"。

## 6. 测试管理

- 用例管理：TestLink / Zentao / 自研。
- Bug 流转：Jira，严重度分 P0–P3，SLA 清晰。
- 质量报告：每周测试通过率、Bug 趋势、技术债。
- 发布准入：QA 签字 + 冒烟测试通过。
