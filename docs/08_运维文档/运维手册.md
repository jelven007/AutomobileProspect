# 运维手册

> 文档编号：OPS-LeadOps-001　　版本：v1.0　　日期：2026-10-04　　负责人：张路

## 1. 部署架构

### 1.1 环境
- Dev / QA / Staging / Prod，四套环境独立。
- Prod 跨 3 可用区，关键数据跨 Region 冷备。

### 1.2 基础设施
- Kubernetes 1.28+，Node Pool 分 `cpu-standard / cpu-memory / gpu-a10 / gpu-a100`。
- 对象存储：S3/OSS/TOS，开启版本控制与 Lifecycle。
- 网络：VPC + 私有子网，服务间 mTLS。
- 日志/监控：独立命名空间 `observability`。

### 1.3 CI/CD
- GitLab CI → Argo CD → K8s。
- 分支策略：trunk-based；Feature Flag 控制未完成功能。
- Pipeline：Lint → UT → Build → SAST → 推 Harbor → Argo Sync。
- 发布：灰度 5% → 50% → 100%；一键回滚（Argo Rollback）。

## 2. 部署流程

### 2.1 后端服务
1. 修改代码 → Merge Request → CI 通过 → Argo 自动部署到 Dev。
2. QA 测试通过 → 推 Staging。
3. 发布评审通过 → Argo 创建灰度（5%）。
4. 观察核心指标 30min 无异常 → 推 50% → 100%。

### 2.2 数据任务
- Airflow DAG 变更走 PR → CI 验证 → 合并后自动部署。
- Spark 作业版本化（Jar 带 commit sha）。
- Flink Job 增量升级，Savepoint 保留。

### 2.3 模型
- 训练产物注册到 MLflow。
- Shadow Mode 7 天对比旧版本。
- 推理服务 Triton 加载新版本 → 灰度分流 → 稳定后全量。
- 回滚：切回 Triton 旧版本模型文件。

## 3. 监控与告警

### 3.1 指标体系
- **基础设施**：CPU、内存、磁盘、网络、Pod 数、重启。
- **服务层**：QPS、RT P50/P95/P99、错误率、JVM GC。
- **数据层**：ETL 成功率、延迟、分区数、数据量波动。
- **模型层**：AUC、KS、PSI、线上线下差异。
- **业务层**：圈选次数、触达量、到店率、ROI。

### 3.2 告警分级

| 等级 | 场景示例 | 通知方式 | 响应 SLA |
|---|---|---|---|
| P0 | 核心服务宕机、数据断流 > 15min | 电话 + 企微 | 10min 响应 |
| P1 | 延迟超阈值、模型 AUC 骤降、单 AZ 故障 | 企微 + 短信 | 30min 响应 |
| P2 | 局部异常、低优指标 | 企微 | 工作时间处理 |
| P3 | 容量预警、技术债 | 邮件日报 | 周内处理 |

### 3.3 日志
- 结构化 JSON，字段固定（trace_id/user_id/request_id）。
- PII 自动脱敏（手机号/身份证）。
- 保留：INFO 30 天，ERROR 180 天，审计 180 天。

### 3.4 链路追踪
- OpenTelemetry Agent + Jaeger。
- 采样率：10% 默认，错误/慢请求 100%。

## 4. 容量管理

### 4.1 容量规划
- 每季度评审一次，预留 50% buffer。
- 关注指标：OneID 增长、事件量、存储空间、GPU 利用率、Kafka 滞后。

### 4.2 扩缩容
- 无状态服务：HPA（CPU/QPS 触发）。
- 有状态（Doris/HBase）：手动扩容 + 自动均衡。
- Spark/Flink：按时段动态调度（夜间降配）。

### 4.3 冷热分层
- 对象存储：1 年热，3 年冷，之后归档。
- Doris：3 个月热，6–12 月冷下沉 Iceberg。
- HBase：TTL 一年，老数据归档。

## 5. 故障预案

| 故障 | 影响 | 处置流程 |
|---|---|---|
| Kafka 集群故障 | 实时数据断流 | 切换备用集群 → 批量回补 → 定位根因 |
| Doris 节点宕机 | 圈选变慢 | 自动剔除 → 补节点 → 均衡数据 |
| HBase RegionServer 挂 | 画像点查延迟 | Region 自动重分配 → Redis 兜底 |
| Redis 集群故障 | 热点性能骤降 | 切备用 → 回填热数据 |
| 模型打分异常 | 高意向识别失准 | 回滚旧版本 → 启用规则兜底 |
| 短信/外呼封控 | 触达失败 | 多供应商切换 → 内容合规检查 |
| 数据泄露 | 合规事故 | 启动应急 → 审计溯源 → 上报监管 |
| K8s 控制面故障 | 新部署受影响 | 保留现网 Pod → 临时手动调度 |
| 对象存储限流 | ETL 变慢 | 请求提额 → 分批退避 |

### 5.1 应急响应
1. 发现（监控/告警/用户反馈）。
2. 分级（P0/P1/P2）。
3. 响应（On-Call 介入）。
4. 止血（切流量/限流/降级/回滚）。
5. 复盘（RCA + 整改项）。

### 5.2 On-Call 制度
- 7×24 轮班，SRE + 核心业务开发。
- 每周轮换，交接会议 15 分钟。
- 故障记录 + Blameless Postmortem。

## 6. 备份与恢复

- 对象存储：开启版本 + Lifecycle，关键桶跨 Region 复制。
- Doris：每日全量快照 + 增量 Binlog。
- HBase：每周 Snapshot + 增量 WAL。
- MySQL：每日全量 + Binlog 实时同步。
- Kafka：Topic 7 天保留 + Mirror 到备用集群。
- 恢复演练：季度一次，RPO ≤ 1h，RTO ≤ 4h。

## 7. 安全运维

- 密钥：KMS 托管，季度轮换，访问日志留痕。
- 补丁：操作系统/中间件月度升级，紧急漏洞 24h 内。
- 访问控制：堡垒机 + 最小权限 + 操作录屏。
- 定期扫描：依赖漏洞（SCA）、镜像漏洞、代码（SAST）。

## 8. 成本管理

- 对象存储冷热分层，节省 30%+。
- Spark/Flink 按时段弹性调度。
- GPU 分时复用（白天推理、夜间训练）。
- Doris 冷数据下沉 Iceberg，释放 SSD。
- 每月成本报告，异常上升预警。

## 9. 变更管理

- 所有变更走 Change Ticket（谁、何时、改什么、回滚方案）。
- 高风险变更（DB/网络/密钥）需 CAB 评审。
- 变更窗口：工作日 10:00–18:00，避开大促。
- 禁止周五下午 & 节假日前变更。

## 10. 文档与知识库

- Runbook：每个服务一份，含启动/停止/排障/联系人。
- Playbook：每类告警一份，含诊断步骤。
- 架构图：Git 版本管理，季度更新。
- 故障案例库：Postmortem 归档，季度分享。
